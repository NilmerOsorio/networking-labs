# 🌐 Networking Lab

Welcome to my **Networking Lab**! 🚀

This repository is where I explore computer networking, build network simulations, and document what I learn through hands-on activities using **Cisco Packet Tracer**.

I want to understand how devices communicate and how networks support the applications we use and build. Beyond configuring devices or following instructions, I want to understand **why each configuration is needed, how it affects communication, and how to identify problems when something doesn't work.**

My goal is to **connect networking theory with practical experience** and strengthen my technical skills through each activity.

## 🎯 What You'll Find Here

- 🔀 **Switching & VLANs:** Activities focused on network segmentation, access ports, and trunk links.
- 🧮 **IP Addressing & Subnetting:** Exercises to understand network addressing and organize devices into subnets.
- 🛣️ **Routing & Connectivity:** Practice configuring communication between different networks.
- 🧪 **Network Simulations:** Cisco Packet Tracer projects for exploring network behavior.
- 🔍 **Verification & Troubleshooting:** Commands, connectivity tests, and evidence used to evaluate configurations.
- 📝 **Learning Notes:** Configuration decisions, challenges, and lessons learned.

*The topics will grow as I explore more networking concepts.*

## 🧰 Tools & Technologies

The tools and concepts I use or plan to explore include:

- **Network Simulation:** Cisco Packet Tracer.
- **Device Configuration:** Cisco IOS commands for switches and routers.
- **Networking Fundamentals:** IPv4 addressing, subnetting, Ethernet, VLANs, trunking, and routing.
- **Documentation & Version Control:** Markdown, Git, and GitHub.

Each activity includes the files and documentation relevant to its requirements.

## 📚 My Learning Approach

I want to understand the reasoning behind a working network and develop the skills to troubleshoot it independently.

For each activity, I aim to:

1. 💡 Understand the requirements and expected network behavior.
2. 🗺️ Review the topology and plan the addressing and connections.
3. ⚙️ Configure the necessary devices and network features.
4. 🔎 Verify settings using relevant device commands.
5. 🧪 Test connectivity and investigate unexpected results.
6. 📝 Document the process, evidence, and lessons learned.

A successful connectivity test is one part of the process. Explaining **why communication works—or why it should be restricted—is part of the learning too.**

## 🌱 The Bigger Picture

Understanding networks helps me see how information travels, how devices find each other, and how configuration decisions affect communication.

This repository represents my journey toward building a stronger foundation in **networking, logical thinking, and problem-solving**.

I'm here to practice, make mistakes, troubleshoot, and improve—one lab at a time.
